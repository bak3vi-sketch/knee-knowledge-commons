# Security Policy

During the foundation phase, do not post suspected vulnerabilities in public issues if disclosure could expose user or patient data.

Before any website or patient-data system launches, establish:
- a private vulnerability-reporting channel;
- incident-response ownership and escalation;
- dependency and secret scanning;
- least-privilege access controls;
- protected production credentials;
- backups and restore testing where applicable;
- logging/auditability appropriate to sensitive operations;
- a data-breach response process;
- security review for external AI/provider integrations.

Changes involving patient data, consent, authentication, authorization, or security controls are Class D under `GOVERNANCE.md`.
