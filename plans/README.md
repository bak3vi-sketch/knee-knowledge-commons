# Plans

`ROADMAP.md` defines long-term direction. Files in this directory define executable, bounded stages. `CONTINUITY.md` identifies which plan/work is active **now**.

## Plan rules
- One plan should have a clear problem, scope, non-goals, deliverables, safety/privacy considerations, acceptance criteria, and dependencies.
- Do not begin a later stage merely because code/content can be produced; satisfy the previous stage's exit conditions.
- Significant scope changes should update the active plan before or with implementation.
- Agents should cite the active plan in PR descriptions for non-trivial work.
- When meaningful progress, blockers, scope, acceptance criteria, or completion state changes, update the active plan and `CONTINUITY.md` as appropriate.
- Completed plans remain in the repository as decision/history context rather than being silently rewritten into a different project.
- Do not create a second status/plan file for the same work; use `CONTINUITY.md` for live state and the relevant plan for bounded execution details.
